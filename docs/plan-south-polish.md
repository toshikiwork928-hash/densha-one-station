状態は計画のみ。作業は未着手（2026-10-10 時点）。参考にした画像は動画（特急サザン26号の前面展望、和歌山市→なんば）の画面で、リポジトリには入れない。

## 0. 指摘の整理

ユーザー指摘（2026-10-10）を、実際の走行方向（和歌山市→みさき公園）の順に並べた。

1. 和歌山市駅の景観が足りない。キーノ和歌山（駅ビル）は最低限必要。
2. 紀ノ川を出て加太線の分岐を過ぎたあと、しばらく走ってトンネルに入るころには山道になる。70km/h制限のあたりから山っぽくなる。高野線の山岳ルートほどではないが、山岳ルートらしさがほしい（画像1〜3）。
3. 和歌山大学前を出るとすぐに山道（画像4は発車後、最初のトンネルの手前）。
4. 孝子を出て最初のカーブを越えたあたり。車道と並走している感じが伝われば良い（画像5）。
5. みさき公園の手前（多奈川線の分岐の少し手前）まで、景色は常にこんな感じ（画像6。おおむね合っている）。
6. みさき公園駅の周りが開けすぎている。先頭からの景色は画像7。もう少し調べる。
7. 和歌山大学前は、停車から発車まで25秒以内だった。ゲーム内でも同じくらいにしたい（早く着きすぎた場合は仕方ない）。

## 1. 和歌山市駅（キーノ和歌山）（実装済み・概形。2026-10-10）

現状: 駅（2面5線の近似）・検車区・加太線の分岐・留置はある。駅ビルは一般の建物と同じ扱いで、目立つ個別形状は無い。

作業

- キーノ和歌山を、駅舎と一体の大型建物として置く（個別モジュール。他の駅の駅舎モジュールと同じ作り）。
- 周辺（駅前広場・バスのりば・市駅前の通り）を、OSMの建物・道路と合わせて確かめ、不足を補う。

事前調査（ローカル。Web検索が要る）

- キーノ和歌山の位置（駅の何番線側か、何階建てか、ホームとの関係）。公式サイト・OSM・地図の航空写真（見るだけ）で確かめる。不明な値は不明と書く。
- 駅ビルの高さの目安（OSMの building:levels や height があるか）。

担当: 調査はローカル。実装はクラウドでも可（調査メモが渡せるなら）。

確認: 和歌山市着の下り終盤と、和歌山市始発の上りで、駅ビルが車窓に入るか。検査カメラ（`?inspect=1`）で壁・屋根が線路にかからないか（`verify:clearance`）。

## 2. 和歌山市〜みさき公園の山あいの区間（実装済み・概形。2026-10-10）

現状

- 山の地形（国土地理院の標高）は `MOUNTAIN` の範囲だけ線路際まで広げている（`src/route/routes/misaki-wakayamako.ts`。みさき公園の先250mから和歌山大学前の手前450mまで）。この範囲は家も補わない。
- 紀ノ川〜和歌山大学前の間と、和歌山大学前の先（和歌山市側）は、この範囲に入っていない。ユーザー指摘の「紀ノ川を出てしばらく走ってトンネルに入るころには山道」「和歌山大学前を出るとすぐ山道」と食い違う。
- 擁壁・切土の表現は無い。トンネルは経路データ（`src/data/geometry/south.json`）から入っているが、坑口の周りの切土や擁壁は一般の斜面のまま。

作業

- 山の範囲を紀ノ川の先から和歌山大学前の先まで広げる。和歌山大学前の駅周辺（ホーム前後）は開けたままにする。
- 切土・擁壁を追加する。線路が周囲の地面より低い所（標高データで判定）に、コンクリート擁壁（格子模様）または樹木つきの法面を置く。右側・左側は上り下りで反転する。
- トンネル坑口の周りに、法面とコンクリートの坑口枠を置く。2本が並ぶ坑口を再現する。
- 孝子〜みさき公園は、車道の並走を確かめる。OSMの道路（県道など）が線路の横を通っているか調べ、通っていなければ手で補う。
- 樹木は、線路際を濃く、斜面の上を薄くする。画像1・4・6のような、線路まで枝がかかる緑にする。
- 「高野線ほど山深くはない」ので、地形の起伏を強くしすぎない。

事前調査（ローカル）

- OSMのトンネル・切土・擁壁・道路の位置を取得して、線路のs（距離）に対応させる表を作る。`scripts/osm-scenery.ts`・`scripts/route-geometry.ts` の延長で作れる見込み。
- 70km/h制限区間（画像1付近）の始まる位置。曲線制限として経路データにある。
- 上り・下りで同じデータを共有できること（`reverseRoute` が反転するため、右左の指定は下りの向きで書く）。

担当: 取得・対応表はローカル。描画（擁壁・坑口・法面）はクラウドでも可。

確認: 検査カメラで、画像1〜6に近い位置（紀ノ川の先、和歌山大学前の前後、孝子の先、みさき公園の手前）を撮って比べる。`verify:clearance`（建物・擁壁が線路の限界にかからない）、`verify:scenery`、`verify:routes`。

現状: 島式2面5線・多奈川線の分岐・7100系の留置は作った。周辺は開けすぎ（ユーザー指摘）。

作業

- 保守用の留置線（黄色い保守用車両）と資材置き場を、下りの右手（なんば側、画像7の右）に置く。線路数・長さは調査して決める。

- 架線ビームはトラス形（既存の門型と区別する）。

事前調査（ローカル）

- 「もうちょい頑張って調べて」の指示なので、駅の前後それぞれの方向の写真（見るだけ）を複数探す。

担当: 調査はローカル。実装はクラウドでも可。

## 4. 和歌山大学前の停車時間（作業済み。案Aで実施。2026-10-10）

現状

- 時刻表の停車は25秒（下り急行: 到着370・発車395）。ただし最速の自動運転は351秒に着くので、定時発車まで約44秒（到着19秒前倒し＋停車25秒）待つ。
- 時刻の延ばし方（`scripts/timetable.ts` の `REAL_FLOORS` と上限15秒）が、駅ごとの「到着側のずらし」として残っている。
- 実ダイヤ（動画の駅表示）: 和歌山大学前は12:06着・12:06発。停車は1分未満（25秒以内）。

不明

- ゲーム内の実測（到着から発車可能までの秒数）。戸閉めの時間や、到着の判定時間が加わるかは未確認。作業の最初に測る。

作業案（推奨は A）

- A: 実ダイヤの停車が短い駅（和歌山大学前・孝子・紀ノ川・みさき公園）は、到着側の「ずらし」を0秒にして、最速で着いた人が約25秒で発車できるようにする。走行時間を延ばしたい分は、駅間の別の位置（後続の駅の到着）に回す。
- B: 現状のまま、上限を駅ごとの値にする（短い停車の駅だけ0秒、尾崎の接続待ちなど実際に待つ駅は上限なし）。

どちらでも、尾崎の緩急接続（普通が優等を待つ）と、和歌山市・和歌山港の折り返し待ちは触らない。

確認: `npm run timetable` の結果を、最速到着と定時発車の差で一覧にして、25秒前後になるか見る。`verify:routes`、`verify:oncoming`（対向列車との行き違いがずれないこと）。

## 5. 順序と分担案

1. 停車時間（4）。小さく、他に影響しない。ローカルで測って直す。
2. 調査（1・2・3の事前調査）。ローカル。結果は `docs/south-scenery-research-3.md`（新規）にまとめる。
3. 山あいの区間（2）。調査結果を渡して、クラウドまたはサブエージェントで実装。
4. みさき公園駅（3）・和歌山市駅（1）。同じく調査結果を渡して実装。
5. 各段階で、`typecheck`、`verify:scenery`、`verify:clearance`、`verify:routes`、`verify:oncoming` を通し、検査カメラで画像と見比べてから公開する。

クラウドの残りは約20ドル。調査をローカルで終えてから渡す方針（クラウドはWeb検索が弱い）。

作業
