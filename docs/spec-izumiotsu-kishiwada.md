# 仕様書: 南海本線 泉大津〜岸和田（新コース）と特急サザン

作成日: 2026-10-06。次のセッションで実装する。実装の進め方は [prompt-izumiotsu-kishiwada.md](./prompt-izumiotsu-kishiwada.md)、堺〜難波の計画は [plan-sakai-namba.md](./plan-sakai-namba.md)。

「確定」はユーザーが明言した内容。「要確認」は私（Claude）の推測や未調査で、実装前に調べるか、ユーザーに聞く。

## 1. 位置づけ

- 南海本線を3つのデータに分ける方針の1つ目として、**泉大津〜岸和田**を別コースで作る（既存の「堺〜泉大津」は変えない）。
  - 難波〜堺（未着手・計画のみ）／堺〜泉大津（既存）／泉大津〜岸和田（今回）
- 区間の境目になる駅（泉大津）の線路・ホームの形は、既存の堺〜泉大津側と**そろえる**（あとで通しにするとき、つなぎ目で形がずれないように）。
- 単体で遊べること。メニューで区間を選べること（案: 「南海本線」を選ぶ → 区間を選ぶ）。
- 方向: 下り（泉大津→岸和田、和歌山方面）と上り（岸和田→泉大津）。上りは `reverseRoute` で作る既存の仕組みに乗せる。

## 2. 駅と区間（確定）

泉大津 → 忠岡 → 春木 → 和泉大宮 → 岸和田（追加するのは 忠岡・春木・和泉大宮・岸和田 の4駅）。

| 区間 | 地形（確定） |
|---|---|
| 泉大津 | 高架駅（既存）。泉大津を出ると、地上へ降りる。 |
| 泉大津〜和泉大宮 | 地上を走る。 |
| 和泉大宮〜岸和田 | 高架で登っていく。 |
| 岸和田 | 高架駅。**屋内式**（屋根が完全につながっている）。ホームに入ると外は見えない。 |

- 配線（島式・相対式・待避線の有無・渡り線）は、配線略図.net の図を読む: https://www.haisenryakuzu.net/documents/pr/nankai/main/ の `figures/011_04.svg`（泉大津・忠岡・春木・和泉大宮）と `figures/011_05.svg`（岸和田）。SVG は `curl -sL` で取得でき、XML としてパースして座標を読める。
  - 注意: このサイトは「石津〜羽衣間は高架化工事のため最新の配線を反映していません」と書いている。泉大津〜岸和田の図は、読んでから現況と食い違いがないか確認する（岸和田の高架・屋内駅など）。
- 線路の形（直線・カーブ）と駅間距離: 地図を検索して読む。必要ならユーザーが地図の画像を `docs/` か、Claude のセッションの画像フォルダに用意する。距離は営業キロ（要確認: 公式の駅間キロ）を優先する。
- 駅名は実名。読み仮名（放送はカタカナ変換される）: いずみおおつ・ただおか・はるき・いずみおおみや・きしわだ。

### 岸和田駅（屋内式）の描画（確定の要件 + 設計案）

- ホーム全体を覆う屋根と壁で、**ホームに入ったら外が見えない**（駅の前後の開口部だけ見える）。
- 設計案:
  - ホーム区間を「室内」として、天井・側壁・床の大きな箱で囲う（トンネルに近い扱い）。
  - 室内では、環境光を落とす（時間帯の太陽光・影・空・遠景を切る。`ctx.light` のトンネル値と同じ扱い）。ホーム照明で明るくする。
  - 音は、トンネル同様に反響を足す（`running.setTunnel(true)` の仕組みを流用）。
  - 天井が低いので、運転台カメラの視界や信号の見え方（出発信号の位置）を確認する。
  - 建築限界の検査（`npm run verify:clearance`）では、壁・屋根・柱が線路・ホーム縁に触れないこと。
  - 描画負荷は、遠くから見えるとき簡易形状にする（距離カリング）。

## 3. 泉大津の「2棟並びのタワーマンション」（確定）

- 駅の東側（要確認: 「東側」=内陸側。海は西側）に建つ、**90年代初頭に建てられた、2棟が並ぶタワーマンション**。この描画だけは入れる。
- 実在の看板・ロゴは入れない。汎用の外観（バルコニーの水平線、屋上設備）にする。年代感として、羽衣のタワー（`world/coastal-tower.ts`）より少し古い意匠（タイル調の外壁色、窓割りが規則的）にするとよい。
- 配置は、**泉大津駅のデータに属する景観**として作り、堺〜泉大津側のコースでも岸和田側のコースでも、同じ物理位置に見えるようにする（共通のランドマーク関数にする）。
- 高さは要確認（20〜30階前後、約70〜100m）。夜は窓明かり（`onLight` 連動）。距離カリング・バッチで負荷を抑える。
- `world/coastal-tower.ts`（羽衣のタワー）の仕組みを流用できる。2棟を並べて描く。

## 4. 特急サザン（確定: 構成・放送／要確認: 外観・停車駅）

### 4.1 編成（確定）

- **8両固定** = 10000系（サザン）4両 + 7100系 4両。
  - **岸和田（和歌山）側が10000系**、**難波側が7100系**。
  - 下り（岸和田方向）では、先頭が10000系（運転台の外観も10000系）。上りでは、先頭が7100系になる。
- 主回路は**抵抗制御**（既存の `audio/resistance.ts` を使う。7100系・10000系ともに抵抗制御）。性能は 7100系（`TRAIN_PERF['commuter-old']`）をベースに、最高速度 110km/h を確認（要確認: 実際の最高速度と加減速）。
- 編成は固定（車両タブでの編成選択はなし、または1択）。

### 4.2 実装上の要点

- 現在の車両の編成は、`ServiceSpec.units: number[]`（ユニットの両数だけ）で、**車種は編成で1つ**（`kind`）。サザンは**ユニットごとに車種が違う**ので、編成の表現を拡張する必要がある。
  - 案: `units` を `{ kind: TrainKind; cars: number }[]` にするか、`unitKinds?: TrainKind[]` を足す。既存の路線（汎用の `units: number[]`）は互換のまま動くこと（旧形式の保存データも）。
  - 影響箇所: `world/train-models.ts`（`createTrainSet`）、`world/player-train.ts`、`world/overtaking.ts`、`world/oncoming.ts`、`ui/vehicle-preview.ts`、`ui/overlay.ts`（車両タブ）、`route/service.ts`（`applyVehicles`）、`game/state.ts`（選択の保存）。
- 新しい車種: `TrainKind` に `'southern-10000'` を追加（10000系の外観: 要調査。座席指定車の窓割り・前面・塗装。架空塗装でよいが特徴は実車寄せ。画像の転載・トレースはせず、特徴を自分の言葉で）。7100系は既存の `commuter-old` を使う。
- 連結部: ユニットの境（10000系と7100系の間）は、運転台付き同士が向かい合う既存の連結表現を使う（高さ・幅が違う車体の連結部は不自然にならないように）。
- 新しい種別: `ServiceId` に `'southern'` を追加（名称「特急サザン」）。種別色は特急の赤系とは別に決める（要確認）。

### 4.3 停車駅（要確認）

- 実際の特急サザンは、堺の次は岸和田（付近）まで停まらない（ユーザーの説明）。
- 泉大津〜岸和田のコースでは、**泉大津（始発）→ 岸和田（終着）で、忠岡・春木・和泉大宮は通過**。
- 既存の特急（50000系）、急行、普通の停車駅・時刻表も、この区間分を作る（普通: 全駅。急行: 泉大津と岸和田が基本で、他は実際の停車駅を調べる）。
- 行先表示と放送の行先は、区間の終点（岸和田）ではなく、**列車の本来の行先**にする: 下りは「和歌山市」、上りは「難波」。種別・行先の LED（`ServiceSpec` に表示用の行先 `destination?: string` を足す案）と放送の両方で使う。

### 4.4 車内放送（確定）

- サザンを選んだとき、**出発時の放送**を次の文面にする:
  > この電車は、一部座席指定、特急サザン{行き先}行きです。次は〜
  - `{行き先}` は 列車の行先（下り: 和歌山市）。読みはカタカナ（ワカヤマシ）。
  - 「次は〜」は既存の文面（通過駅を飛ばすときは「次は、○○に停まります」）。
  - 実装箇所: `audio/announce-text.ts` の `departText`（始発駅の挨拶部分）。サザンのときだけ文面を切り替える。
- **普通車の放送**: 一部の文面を変えたい（ユーザーから、変更点を別途伝える）。実装前に、ユーザーに確認する。現状の普通の文面は `audio/announce-text.ts` の `approachText` / `arriveText` / `departText` と `waitPhrase` / `connectPhrase`。

## 5. 時刻表・運転・検証

- 時刻表は `npm run timetable`（`scripts/timetable.ts`）が自動生成する。新コースと新種別（サザン）に対応させる。
- ATS・信号・閉そく・待避: 既存の仕組みに乗せる。泉大津〜岸和田で待避駅があるかは、配線図で確認する（要確認）。
- 終着の ATS: 南海本線は現在「終着の低速進入 ATS」を無効にしている（`terminalApproach: false`）。新コースも同じ扱い。
- 検証:
  - `npm run typecheck`・`npm run build`
  - `npm run verify:routes`（新コースを追加して、全種別・上り下りで完走、罰点0、速度超過0）
  - `npm run verify:scenery`
  - `npm run verify:clearance -- --all`（約15分。新コースのケースを追加して違反0。屋内駅の壁は、車止めのように意図的な例外にしない）
  - 画面での確認: 泉大津・和泉大宮の高架への登り・岸和田の屋内駅（運転台と外から、昼・夕・夜）、泉大津のタワー、サザンの編成（連結部、前面、ドア、夜の窓明かり）。

## 6. 負荷の目安

- 現在の泉大津〜堺（10.6km）で、世界全体の三角形は約200万。泉大津〜岸和田（約6km）を別コースにすると、起動時の負荷は同程度になる想定。
- 新コースを足したあと、起動時間・メモリ・三角形数・実機の fps（Xiaomi 14 Ultra、Pixel 10 Pro Fold）を測る。
