# 泉佐野以南のコース（泉佐野〜みさき公園、みさき公園〜和歌山港）

作成日 2026-10-09。先に走れる状態にして Pages に出し、景観・ダイヤは後から作り込む方針（ユーザー指示）。§1〜§6 は実装前の資料。みさき公園〜和歌山港の実装は §7。泉佐野〜みさき公園は未実装。

## 1. 作るもの

- 泉佐野〜みさき公園。10駅・17.9km。上り・下り。
- みさき公園〜和歌山港。6駅・15.1km（みさき公園、孝子、和歌山大学前、紀ノ川、和歌山市、和歌山港）。上り・下り。和歌山市は途中駅。
- 種別は普通と特急サザンだけ。日中の実際の運転に合わせる。ラッシュ時の急行・区間急行・空港急行は後回し。
- 景観は、建物・細かい部品・OSM の街並みを入れない。線形、勾配、トンネル、橋、駅、地形だけ。
- ダイヤは、これまでと同じゲーム用の自動生成（最速走行に余裕を足したもの）。対向列車は置かない。実ダイヤの再現は後回し。

## 2. 線形・勾配・構造物の下書き

`npm run geometry:south` が `src/data/geometry/south.json` を作る（`scripts/route-geometry.ts`）。ローカルだけで動く（Overpass と国土地理院の標高 API に接続する）。路線データを書く人が読む材料で、アプリは直接読まない。

作り方
- OSM の線路の中心線を、上下線の点の平均で作る。駅の間は営業キロへ伸縮する。
- 伸縮率が 0.95〜1.04 に収まった。中心線が実際の線路に沿っていることの確認になる。
- 線形は、進行方向の角度の変化を折れ線で近似し、直線と円弧にする。ホームの範囲（停止位置の手前190m〜先60m）は直線にして、失った角度は直後の300mで戻す。
- 勾配は、国土地理院の標高（5mメッシュ）を100mごとに取り、300m区間の平均を5‰刻み、±25‰以内にする。トンネルと長い橋の中は、地面でなく出入口の標高の直線補間にする。ホームの範囲は水平。

確認した数値（2026-10-09）
- OSM の中心線 32.8km、営業キロ 33.0km（泉佐野〜和歌山港）。
- 円弧 238個、最小半径 103m。半径の大きな円弧が多く、実際の曲線ではない。細かい曲線は概形。
- 再構成した線形と OSM の中心線の最大ずれ 71m。
- 勾配から再構成した標高と地面の最大差 16.0m（和歌山港線の終端付近）。最大勾配 25‰。

OSM から取れた構造物（営業キロ s [m]）
- 橋。s 0〜1781（泉佐野の高架）、4079〜4192、8038〜8196、12807〜12834、16617〜16650、28593〜29243（紀ノ川橋梁と推定）、31524〜31602、32645〜32868。川の名前は未確認。
- トンネル。s 22729〜23418、25354〜25430、25487〜25605。Wikipedia の第一孝子越隧道・第二貴志隧道・第三貴志隧道と、数が一致する。どれがどれかは未確認。

## 3. 駅

配線は配線略図.net の `figures/011_06.svg`〜`011_08.svg`。構造は Wikipedia と配線図。南端の和歌山港線は単線。

営業キロは泉佐野起点 [km]。

- 泉佐野 0.0。高架・島式3面4線。別作業（B）で作り直し中。コースの始発駅は、その駅の定義を使う。
- 羽倉崎 2.1。地上、島式（1・2番）と単式（3番）の2面3線。駅舎は3番線側で、連絡地下道。1番線は羽倉崎検車区につながる。サザン・急行は通過。区間急行・普通は停車。
- 吉見ノ里 3.4。地上・相対式2面2線。駅舎はなんば側のホーム、構内踏切でつなぐ。
- 岡田浦 4.8。地上・相対式。駅舎はなんば側ホームの両端、連絡地下道。
- 樽井 6.6。地上、2面3線（上りホームは島式）。跨線橋。駅舎は和歌山市側。なんば側に下り線から上り線への渡り線があり、折り返し普通が使う。男里川橋梁が尾崎との間にある（2017年の台風で損傷）。
- 尾崎 9.1。地上・2面4線（待避線あり、配線図）。Wikipedia の記事は取得できず、ホーム形式の詳細は不明。サザンは停車。
- 鳥取ノ荘 10.6。地上・相対式。2016年に南口。
- 箱作 12.6。地上・相対式。ホームごとに駅舎と改札があり、ホーム間は行き来できない。
- 淡輪 16.2。地上・相対式。1925年の洋風木造駅舎がなんば側ホーム。地下道。
- みさき公園 17.9。盛土上・島式2面5線（配線図）。多奈川線の起点。サザンは停車。難波側にかつて構内踏切があった。
- 孝子 22.3。地上・相対式。なんば側ホームに駅舎、構内踏切。日中は普通のみ停車、1時間約4本。隣のみさき公園との4.4kmが路線で最長。
- 和歌山大学前 24.0。地上・相対式、橋上駅舎。サザンは2014年10月から停車。
- 紀ノ川 27.6。相対式2面2線（配線図）。加太線が分かれる。Wikipedia の記事は取得できず、ほかは不明。
- 和歌山市 30.2。地上・2面5線。南海本線の終点。3番線は加太線、4・5番線は和歌山港線にも通じ、7番線は和歌山港線の普通が使う。配線図では、和歌山港線が駅の南端からそのまま続く。向きを変える折り返しは、この配線図からは読み取れない。
- 和歌山港 33.0。築堤上・島式1面2線、8両編成分。改札は2階、ホームは3階。2番線は行き止まり。終点。

## 4. 種別と停車駅

- 普通。全駅に停車。ただし実際には、和歌山港線の普通は線内折り返しで、本線の普通は和歌山市止まり。みさき公園〜和歌山港の1コースでは、普通が和歌山市を越えて走る。実際には存在しない運転で、ゲーム用の扱い。
- 特急サザン。泉佐野、尾崎、みさき公園、和歌山大学前、和歌山市（一部は和歌山港）に停車。羽倉崎、吉見ノ里、岡田浦、樽井、鳥取ノ荘、箱作、淡輪、孝子、紀ノ川は通過。
- 急行は、羽倉崎〜淡輪の各駅を通過する。ラッシュ時の運転で、今回は入れない。

不明
- 和歌山港線の最高速度。本線は110km/h（Wikipedia）。
- 日中の普通・サザンの1時間あたりの本数（ダイヤ再現を後回しにするので不要）。

## 5. 実装時の決めごと

- 路線データは、`src/route/routes/` に新しいファイルを足し、`src/route/index.ts` の南海本線の区間に登録する。
- 駅の配置は、既存の駅形（relative、loop、custom）に当てはめる。尾崎は loop（2面4線）、みさき公園は loop か custom、それ以外の地上駅は relative。
- 時刻表は `npm run timetable` で生成する。
- 検証スクリプトの、対向列車を前提にした部分は、新コースを対象から外す。
- 景観は、OSM データなしで開始できること。必要な最低限（地面、空、線路、架線、トンネル、橋）は既存のものを使う。
- 画面確認は、ローカルで `?inspect=1&route=<id>` を使う。

- 種別は普通と特急サザン。サザンの停車は泉佐野、尾崎、みさき公園。時刻表は `npm run timetable -- --south-only` で生成（自動運転の最速走行 +5%）。
- 対向列車・踏切・小さな橋（川）・OSM の建物は未作成。検証は `verify:routes`（新コース2本を追加）と `verify:clearance` の対象に追加済み。`verify:oncoming` の対象には入れていない。

## 7. みさき公園〜和歌山港の実装（2026-10-09）

コース id は `misaki-wakayamako`（下り、みさき公園 → 和歌山港）と `misaki-wakayamako-up`（上り）。南海本線の区間一覧（`route/index.ts` の `NANKAI_SECTIONS`）の末尾に「みさき公園〜和歌山港」として追加した（既定の区間は変えていない）。

### ファイル

- `src/route/routes/misaki-wakayamako.ts` … 路線データ。上りは `reverseRoute`。
- `src/route/routes/misaki-wakayamako-geometry.ts` … 線形・勾配・構造物。`npm run geometry:misaki-wakayamako`（`scripts/slice-south-geometry.ts`）が `src/data/geometry/south.json` から切り出して生成する。ネットワーク不要。
- `src/route/routes/misaki-wakayamako-timetable.ts` … 時刻表。`npm run timetable`（`scripts/timetable.ts`）が生成する。`-- --misaki-wakayamako-only` でこのファイルだけ更新できる。
- `src/data/osm/misaki-wakayamako.json` … 手作りの水面1枚（OSM のデータではない）。「景観」の川の項。
- 変更: `world/terrain.ts`（地面が線路に沿うモード、水面の高さ）、`world/osm-town.ts`・`town-jp.ts`・`scenery.ts`（水面だけのデータの扱い、`Terrain.low`）、`world/mountain-terrain.ts`（`Terrain.low` の実装）、`world/track-mesh.ts`（追加の線路が無くても頭端駅の終端に車止めを作る）、`route/service.ts`（サザンのTOP選択）、`route/types.ts`（`groundFollowsTrack`、`viaductHeight`）、`scripts/`（時刻表・clearance・verify:routes・oncoming-meets）。`scripts/oncoming-meets.ts` は実ダイヤの距離（KM）を持たないコースを対象から外した。`verify:oncoming` は対象のコース id を列挙しているので、新コースは対象外（対向列車なし）。
- 注意: `npm run timetable` を引数なしで全部流すと、既存の `local-timetables.ts`・`shiokaze-timetable.ts`・`through-timetable.ts` に差分が出る（今回の変更の前の master でも同じ。生成結果とコミット済みの値が元から食い違っている）。既存の時刻表は書き換えず、新コースのファイルだけ `-- --misaki-wakayamako-only` で生成するのが安全。

### 線形・勾配

- south.json の s=17720（みさき公園のホームの直線の中。直線は 17703.7〜17955.1）を s=0 とする。みさき公園の停止位置（south.json の s=17900）が s=180。以降の線形・勾配・構造物・駅は -17720。和歌山港（south.json の s=33000）の先は直線を 100m 延ばした。総延長 15280.18m + 100m、線形 123 要素。
- 駅の停止位置 s は、みさき公園 180、孝子 4580、和歌山大学前 6280、紀ノ川 9880、和歌山市 12480、和歌山港 15280。各駅のホーム（停止位置の手前 180m〜先 40m）は直線・水平（`verify:routes` が検査）。
- 標高はみさき公園の地面を 0（`elevation0 = 0`）にして、gradients を積分しただけ。ホームは水平。標高は孝子 +38.5m、最高 +47.1m（s=5380、第一トンネルの中）、紀ノ川 -9.7m、和歌山市 -8.2m、和歌山港 -3.7m。
- gradients を積分した標高と、south.json の地面の標高（国土地理院）の差は、孝子で 0.3m、和歌山大学前で 2.3m、紀ノ川で 9.5m、和歌山市で 10.3m、和歌山港で 8.3m（この区間の最大 11.6m）。5‰ 刻み・±25‰ の丸めで差が溜まったもの。直すには south.json の勾配の作り方を変える必要がある（今回は指示どおり gradients のまま）。
- 曲線制限はゲーム用。半径 R の円弧ごとに 3.8√R km/h を 5 の倍数に切り下げ、90km/h 未満になるものだけ置いた（最も厳しいのは孝子の手前 R103 の 35km/h）。south.json の円弧は実際の曲線ではなく概形なので、実際の制限速度とは一致しない。

### 駅の形

- みさき公園: 盛土上・島式2面5線 → 島式2面4線（`loop`、待避線の形は岸和田〜泉佐野と同じ）。多奈川線・5線目は描かない。普通は始発・終着で待避線に入り（分岐器 45km/h）、サザンは本線のホームに停まる。盛土の高さは不明のため地面と同じ高さにした。番線名は不明のため案内しない。
- 孝子・和歌山大学前・紀ノ川: 地上・相対式2面2線（`relative`）。橋上駅舎・構内踏切・加太線の分岐は描かない。
- 和歌山市: 地上・2面5線 → 途中駅の相対式2面2線（`relative`）。3〜7番線・加太線・和歌山港線の配線は描かない。
- 和歌山港: 築堤上・島式1面2線の終点（`island` + `headEnd` + `elevated`）。線路が駅の前後で左右へ 3.9m ずつ開き（線間 11.8m）、幅 8.4m の島式ホーム。ホームの先 35m に車止め（`extent.to`）。8両分（160m）が入る。ホーム幅・線間・築堤の高さは不明（ゲーム用の概形）。
- 終着の仕組み: 既存の `headEnd`（車止め、`track-mesh.ts`）と `terminalApproach`（`game/terminal-ats.ts`。残り 1000m から 65 → 10km/h の連続速度照査）。下りは `terminalApproach: true`、上りは終着がみさき公園（途中駅）なので false。
- 終点の番線は不明。ゲーム用に、下りは 2番線（島式ホームの左の線）、上りは 1番線（反対側の線）に入る・発車する。2番線が行き止まりという §3 の記述に合わせた。
- 路線全体を複線（`tracks: [0, 4]`）で描く。実際の和歌山市〜和歌山港は単線なので、その区間は実際と違う（ゲーム用の簡略化）。

### 種別と時刻表

- 普通: 4両（4・4+2・6両）、全駅停車、最高速度 90km/h。車種の選択肢は岸和田〜泉佐野の普通と同じ。待避なし。
- 特急サザン: 10000系 + 7100系の8両、みさき公園・和歌山大学前・和歌山市・和歌山港に停車（孝子・紀ノ川は通過）、最高速度 110km/h。上りは 7100系が先頭（既存コースと同じ）。
- 行先は、下りは両種別とも和歌山港、上りは両種別ともなんば（既存の上りコースと同じ扱い。実際には存在しない運転）。
- TOP の種別選択: `selectableServices` の規則に従い、特急サザンは両端が実際の停車駅のときだけ選べる。サザンの停車駅に、みさき公園・和歌山大学前・和歌山市・和歌山港を加えた（ラピートβの規則は変えていない。既存コースの選択は変わらない）。
- 時刻表は、既存と同じゲーム用の自動生成（最速走行 +5%、停車 25 秒）。下りの所要は普通 1060 秒、サザン 985 秒。上りは普通 1025 秒、サザン 950 秒。実ダイヤの再現ではない。

### 景観

- OSM の建物・道路データは作らない。街並みは既存の手続き生成（`town-jp.ts`・`scenery.ts`）で、まばら。`route.scenery.cityZones` は和歌山市の周辺（s 11700〜13300）だけ市街地で、孝子〜和歌山大学前は市街地にしない。対向列車・踏切は置かない（`oncoming: []`、`crossings: []`）。信号は岸和田〜泉佐野と同じ作り方。
- 地形: 標高が正の山あい（孝子の +38m など）では、従来の地面（高さ 0、線路が高ければ盛土）が使えないので、`Route.groundFollowsTrack` を追加した。true のとき地面が線路の高さに沿い、橋・高架・トンネルの所だけ地面と線路の高さが違う。川の水面は、橋の前後の地面から 3.6m 下に置く。既存コースは未指定（従来どおり）。建物・木を置かない低地の判定は `Terrain.low(s, m)` にまとめた（既存コースは従来と同じ式）。
- 川（紀ノ川橋梁）: OSM の水面データが無いコースでは、`terrain.ts` の橋の溝（`riverDip`）だけが残る。溝は橋の範囲に沿って、線路の両側それぞれ約16mまでの細長い帯で、川の幅にならない（コードから見積もった値。画面での確認は親セッション）。そのため、橋の両端から 100m 内側（s 10973〜11423）を、線路に直角な幅 450m・長さ 1800m の水面1枚にした手作りのデータ `src/data/osm/misaki-wakayamako.json` を、既存の `loadOsmFor`（区間データの別チャンク）で読む。川幅・向き・水際の形は不明の仮値。ビルドでできる追加チャンクは `misaki-wakayamako-*.js`（0.56kB）。水面だけのデータは `DATASETS` の `waterOnly` で、街並み（OSM の建物・道路）を作るデータと区別する。小さな橋（78m）には水面を足していない。
