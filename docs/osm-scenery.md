# 景観の地図データ（OpenStreetMap）

作成日: 2026-10-08。堺〜なんばの線路沿いの景観を、OpenStreetMap（OSM）のデータに基づく配置にした（段階A）。完全な再現ではなく、配置・密度・道路の並走・緑地・ランドマークの位置を実物に寄せる。

## 出典

© OpenStreetMap contributors（ODbL 1.0）。Overpass API で取得。国土地理院の地図は使っていない。

## 手順

```bash
npm run osm:scenery -- --course=namba            # 取得（Overpass）→ 変換 → src/data/osm/namba.json
npm run osm:scenery -- --course=namba --offline  # 取得済みのキャッシュ（node_modules/.cache/osm/）から変換だけ
npm run osm:scenery -- --course=namba --endpoint=https://overpass.kumi.systems/api/interpreter  # 別のサーバー
```

- クラウドの開発環境からは Overpass へ接続できないことがある（相手側で切断される）。その場合はローカルで実行してデータをコミットする。
- 生データ（数十MB）は `node_modules/.cache/osm/` に置き、コミットしない。コミットするのは簡略化したデータ（約0.7MB）だけ。

## 取得するもの（線路の両側 320m）

建物、道路（都市高速〜生活道路）、公園・庭園・運動場、草地・森・墓地・社寺の敷地、水面・川、学校、社寺、駐車場。relation（multipolygon）は外周の way を端点でつないだ輪にする（`out geom` で member の形も取る）。線路は `name` に「南海本線」を含む `railway=rail`、駅は `railway=station` の駅名。

## コースの座標への写し方

1. 線路（上下線・複々線）の点を駅間ごとに 10m の区切りで平均し、中心線を作る。
2. 各点を中心線へ射影し、中心線に沿った距離 c と、符号付きの横距離 d（進行方向の右が正）を得る。
3. c は駅の中心どうしの間で線形に伸縮して、ゲームの s（ホームの中心の s）に合わせる。コースの線形（`src/route/routes/namba.ts`）も OSM の線路形状を駅間ごとに営業キロへ伸縮して作ってあり、同じ写し方になる。
4. 横位置は d に、ゲーム側の本線群（上下本線・複々線の緩行線）の中心の横位置を足す。

## データの形（`src/data/osm/<course>.json`）

| キー | 中身 |
|---|---|
| `buildings` | `[s, lat, 長さ, 幅, 角度(度), 階数, 種類]`。外接長方形。種類は h 戸建て / a 集合住宅 / c 商業・事務所 / i 工場・倉庫 / r 社寺 / p 学校・公共 / g 車庫・小屋。階数は `building:levels`・`height` から、無ければ種類と面積から推定 |
| `roads` | `[等級, 幅, 名前, s,lat の並び]`。等級 1 = 国道・幹線、2 = 主要地方道・一般道（紀州街道など）、3 = 生活道路。同じ等級・名前の way は端点でつないで長い線にする |
| `highways` | `[幅, s,lat,高さ の並び]`。都市高速（`highway=motorway*`、阪神高速など）。本線は高さ 12m、ランプは本線側が高く他端が地上 |
| `areas` | `[種類, s,lat の並び]`。park / grass / pitch / school / grave / shrine / wood / water / lot（駐車場）。線路から ±320m の帯で切ってある（範囲の外の頂点は延長線へ写し、辺を 20m ごとに分けてから切る） |
| `landmarks` | 名前のある大きな建物・社寺・公園・池の `[名前, s, lat]`（位置の確認用） |

## 描画（`src/world/osm-town.ts`）

- 線路から 55m 以内の戸建て・アパート・商店・マンションは `town-jp.ts` の部品（窓・ベランダ・看板）で作り、550m まで描く。それ以外は箱と屋根だけで 1.6km まで描く。
- 線路（高架・ホーム・追加の線路）にかかる建物、専用モジュールの敷地（`route.reserved`: なんばの駅ビル・なんばパークス・住ノ江検車区・七道の商業施設・住吉大社の本宮）は置かない。
- 道路・公園・森・池・墓地は地面に貼る。森・社寺・公園・墓地には木を植える（上限はコース 1km あたり 150 本・最大 2400 本。森を優先）。幹線道路には街路樹。
- 下り（なんば → 堺）は `world/namba-frame.ts` の写しで同じ物理位置に描く。
- このコースでは、手続き生成の住宅列・線路沿いの道路と、素材のビル（市街地・遠景）を置かない（遠景のビル群はデータの範囲の外 340m から）。
- 乱数は `ctx.rng` を使わない。

## ランドマーク

- なんばパークス風の段々の建物: 西側（OSM のパークスタワー・住宅棟の位置）へ移した（`world/namba-terminal.ts`）。
- 住吉大社（`world/sumiyoshi-taisha.ts`）: 西の大鳥居、池と反橋、参道と石灯籠、本宮4棟（住吉造の直線の切妻屋根・朱と白・千木と鰹木）と瑞垣。位置は OSM の本宮・池から。森は OSM の森の多角形に木を植える。

## 段階B（堺〜泉大津・泉大津〜岸和田）

- データ: `sakai-izumiotsu.json`（元のコース `shiokaze` = 泉大津 → 堺）、`izumiotsu-kishiwada.json`（`kishiwada` = 泉大津 → 岸和田）。
- 走るコースへの写し方（`osmFor`）: データの元のコースと走るコースの共通の駅の中心をそろえて s を写し、逆向きなら横位置を鏡像（lat' = 左右の線路の和 − lat）にする。区間をつないだ通しコース（堺〜岸和田）は、つなぎ目の泉大津の駅の中心で各データを切って重ならないようにする。下り・通しコースでも同じ物理位置になる。
- 浜寺公園の松林（OSM の森の多角形）、紀州街道の並走、沿線の住宅。
- OSM に建物がほとんど登録されていない区間（春木〜和泉大宮など。道路は登録されている）は、道路・公園・水面を避けて戸建て中心に補う（100m ごと・片側で OSM の建物が 12 棟未満の所）。
- 地上区間では、駅舎・駅前（ホームの前後 12m、線路から 24m。待避線のある駅は 44m）、泉大津駅前のタワー、道路の跨線橋、阪堺線・高師浜線の高架の敷地に建物・道路を置かない。地上の線路を横切る道路は線路の手前で切る（踏切は `crossings.ts`）。
- 建物はすべての線路（本線・追加の線路・2面4線駅の待避線）の中心から 4.5m 以上、外形で離す（`npm run verify:clearance` で違反 0）。

## 作り直し（2026-10-08、公開後の修正）

公開後に実際の素材（建物・木のモデル）を読み込んだ画面で崩れが見つかったため、全区間で作り直した。

| 症状 | 原因 | 対処 |
|---|---|---|
| 大和川の上に家が建つ | 川・池が relation（multipolygon）で、`out tags geom` では外周の形が取れず捨てていた | `out geom` で取り、外周の way をつないで輪にする。範囲の外の頂点は線の延長へ写す。川（`route.structures` の橋の範囲）と水面には建物を置かない |
| 大和川橋梁で阪神高速が線路を跨がない | 都市高速（`motorway`）を取っていなかった（#21 より前の版にも、跨ぐ高架道路の部品は無かった） | OSM の阪神高速を高架で描く（橋脚・桁・壁高欄）。線路の近くは架線の上 10m まで上げ、前後は 6% の勾配でならす。地上へ下りるランプが線路に近い所は描かない |
| 道路がつぎはぎ | OSM の way が交差点ごとに切れていて、継ぎ目・曲がり角に隙間 | 同じ等級・名前の way をつなぎ、端と曲がり角に円盤を足す。等級・面の種類ごとに高さを分けてちらつきを防ぐ。面は s 方向 40m ごとに切って三角形分割（線路の曲がりに沿う） |
| 住吉大社が更地 | 社寺の敷地の木が上限（650 本）で植わらず、池が敷地の面の下に隠れていた | 木の上限をコース 1km あたり 150 本（最大 2400）に。水面を面の一番上に。本宮を囲む玉垣（緑青の笠）・神門・角鳥居を追加 |
| なんばパークス・駅の東側が更地 | 難波の駅ビルの予約範囲（s 9350〜、線路から 95m）が東側の OSM の建物を消していた。パークスの位置が OSM より南 | 予約範囲を駅ビル・大屋根の実際の範囲（s 9740〜）に。パークスを OSM の外形（s 9570〜9850、ホームの西）へ移し、パークスタワーと南西のタワーマンションを置く |
| 空き地が多い | 補いの判定が 100m ごとの棟数だけ、占有を外接正方形で数えていた、駐車場が無地 | 置ける建物の外形（向きのある長方形）で占有を数え、空いた所に線路沿いは 58%・奥は 45% の確率で戸建て・アパートを置く。駐車場には車を並べる。建物の登録のない学校には校舎を1棟 |
| 浜寺公園〜阪堺線の道路 | 阪堺線の跨線橋の手作りの「国道」が短い切れ端で、OSM の道路とつながらない。高架の下の道路も切っていた | 手作りの国道を削除。阪堺線の高架（高さ 4.5m 以上）の下は OSM の道路を通す |
| 羽衣のタワーマンションが2棟 | 手で置いたタワー（`coastalLandmarks` の `tower`）と OSM の建物が両方出ていた | 手で置いたタワー（`world/coastal-tower.ts` の描画）を削除 |

ほかに: 浜寺公園など大きな公園は森に近い密度で木を植える。地上区間の線路の柵を戻す（すべての線路の外側 3.8m）。海沿いのコースの地面を町の色に。地上駅の駅前の空き（建物を置かない範囲）を ホームの前後 12m・線路から 24m（待避線のある駅は 44m）に縮める。浜寺公園の副線・羽衣の3番線も建物の離隔の対象に。

開発時は、ブラウザのコンソールで `__osmWhy(s, lat)` を呼ぶと、その位置に建物を置かない理由（線路との距離・予約範囲・駅前・占有・道路・面）を返す。
