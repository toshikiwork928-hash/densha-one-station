# 計画: 堺〜難波（次回以降に持ち越し）

作成日: 2026-10-06。**2026-10-07 に実装済み**（堺 → なんば の1方向・独立コース）。実装の仕様と調査結果は [spec-sakai-namba.md](./spec-sakai-namba.md)。以下は計画時のメモ。先に [spec-izumiotsu-kishiwada.md](./spec-izumiotsu-kishiwada.md)（泉大津〜岸和田）を作る。

## 方針

- 南海本線を3つのデータに分ける: **難波〜堺（このファイル）**／堺〜泉大津（既存）／泉大津〜岸和田（次回の実装）。
- まず**別コース**として作り、動作・描画・負荷を確認してから、通し（泉大津〜難波、約20km以上）にするかを決める。
- 通しは、特急が活きる（難波〜堺〜岸和田で通過駅が多い）。ただし、全体を一度に作ると起動時間とメモリが増える。通しにするなら、走っている付近の数kmだけ景観を作る「区間ごとの読み込み」が要る（大きな工事）。

## 種別と運行

- 普通・急行・特急（既存）+ **特急サザン**（[仕様書](./spec-izumiotsu-kishiwada.md) の 4章）。
- 難波〜堺では、**特急と急行の停車駅がほぼ同じ**になる（ユーザーの指摘）。区間を別コースにすると、特急が活きにくい。通しにするときに、特急の通過駅（堺〜岸和田など）が活きる。
- 難波〜堺の停車駅は、実際のダイヤを調べて決める（要確認）。
- 方向: 難波→堺が「下り」。上りは `reverseRoute`。

## 実装の順序（案）

1. 泉大津〜岸和田を作る（次回）。サザンの編成（ユニットごとに車種が違う）を、この機会に作る。
2. 現状の負荷（起動時間・メモリ・三角形数・実機 fps）を測って、予算を決める。
3. 難波〜堺を別コースで作る（上の表の特殊箇所は簡略化）。
4. 動作と負荷を確認し、通しにするかを決める。通しにする場合は、区間ごとの読み込みを設計する。

## 通しにする場合の設計メモ

- 路線を1本の `Route` にし、景観を「走行位置の前後 数km」だけ生成して、通り過ぎた区間は破棄する（先読みつき）。
- 区間の境目（堺・泉大津）の線路・ホームの形が、前後の区間データで一致していること（今から揃えておく）。
- 時刻表・信号・ATS・対向列車は、区間をまたいで連続して動く必要がある。`game/` 側は、すでに `Route` 全体を前提にしているので、景観の生成だけを区間化する。
- 負荷の予算を超えるなら、遠景のビルの LOD、線路・バラストのチャンク化（ROADMAP「表現」「技術」の項目）を先にやる。
